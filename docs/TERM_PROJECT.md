## 4. 보고서

- **초안(Claude Docs 공유 문서)** = https://claude.ai/artifact/VRBQoznEJHHgAe8LzEC7ac
  - 1~7장 + 부록. 절마다 초안 본문 + "작성 가이드" 칸.
  - 남은 일 = 문서 **부록 B 체크리스트**가 정본(이 파일에 복사하지 않는다).
- 방향: 펌웨어 구동 제어(피드포워드 + PI, PWM)를 C++ 클래스 구조로 **깊게**, 젯슨은 2장에서 **넓게**만.
  보고서는 "개발 과정"이 아니라 "만든 작품"을 설명한다.
- 구성: 1 작품 개요 / 2 시스템 구현 / 3 펌웨어 설계 / 4 클래스별 구현 / 5 제어 이론과 시뮬 / **6 개발 결과** / 7 결론 / 부록 A·B·C.
- 🔵 **결정(11-22, §96)**
  - **6장 = 개발 결과**: 6-1 주행 성능(실차) · 6-2 미션 동작. 펌웨어 동일성 확인·단위 시험·FMA 는 본문에서 빼고
    **부록 C**(C-0 요약 · C-1 단위 시험 · C-2 비교 · C-3 컴파일러). "클래스로 바꿨다" 는 결과물이 아니다.
  - **4장 코드 설명 = 작품 그 자체**를 클래스별로: 역할 → 구조(선언부) → 핵심 함수 → 숫자 예시 → 강의 연결.
    원본과의 비교는 "왜 이 설계인가" 한두 줄만. 전체 코드는 부록·저장소 링크(새 클래스 헤더만, 원본·안전 헤더는 링크).
  - **7장은 보고서 작성자 몫** — 리뷰하지 않는다. 단 7-3 출처는 과목 규칙(출처 명시)이라 사실 확인 대상이다(미실시).
- **작성 자료** = 같은 문서의 두 번째 탭 "작성 자료" — 리뷰에서 확인한 사실·숫자·코드·사건·질문 대비를 장별로
  모으는 재료 창고. 완성 문장·방향 제안은 넣지 않는다.
- **예시 보고서** = `~/Downloads` 의 공학프로그래밍 최종보고서 4건(PDF). 2019년 3건이 공통 양식
