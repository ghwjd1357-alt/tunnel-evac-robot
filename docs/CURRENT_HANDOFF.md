  `src/tunnel_bringup/**` 가 이 묶음의 금지 범위라 **코드는 구값 그대로다.** 대상 5건 =
  `MASTER_PLAN.md §7` **예약 19** (`MASTER_PLAN.md §3` S6-7 과 한 쌍).
  ⚠ 그중 **① EKF QoS(BEST_EFFORT) · ② Nav2 속도 상한(0.12/0.50)** 은 **D+0 에 바로 터지는**
  항목이다 — ①은 `topic hz` 는 정상인데 EKF 만 조용히 못 받고, ②는 Nav2 가 자기 명령대로
  가고 있다고 잘못 믿는다. **실차 S6 착수 시 최우선.**
- **★ `/odom` 속도 +8.32% 는 열려 있다 (08-02 신설)** — R2 는 **거리 기준으로만** 통과했고,
  우리 EKF 는 **속도만** 쓴다. 3m **소요시간**이 오면 (a) 실제로 빠름(≈139초) / (b) `/odom`
  속도 부풀림(≈150초) 이 갈린다. **(b) 면 EKF 직격**이다. 최종 합의서 요청 4 로 요청했다.
- **★ 게이트 술어 불변조건** (`MASTER_PLAN.md §8` 07-30) — 조건 기동 게이트의 충족 판정은
  **"한 번 관측 = 통과" 금지**. 유효기간을 조이는 것은 보완이 아니다.
- **★ 세대 불변조건** (`MASTER_PLAN.md §8` 07-30) — **비동기 증거는 세대에 속한다.**
  서비스 소실을 관측하면 카운터뿐 아니라 **그때 날아가 있던 요청까지** 무효화한다.
- **★ 증거 수집 불변조건 (07-30 신설)** — 단언이 깨지는 순간의 증거는 **`fail()` 보다 먼저**
  수집한다. `fail()` 은 즉시 cleanup+exit 이라 정작 필요한 순간에 증거가 노드와 함께 사라진다.
- **★ 외부 CLI 상한 불변조건 (07-30 신설)** — `ros2` 든 `gz` 든 **예외 없이** hard 상한을 씌운다.
  **사람이 개입해서 얻은 PASS 는 판정이 아니다.**
- **★ 남은 검증 상한 (닫히지 않았다 — 조건부 수용)**: DDS 가 알아채기 전에(<1폴링) 서버가
  재시작하면 `service_is_ready()` 는 계속 True 라 게이트가 두 세대를 구분할 수 없다.
  `lifecycle_msgs/GetState` 응답에 세대 식별자가 없어 **이 계층에서는 원리적으로 못 닫는다.**
  - **수용 전제**: Nav2 lifecycle 서버는 0.5s 안에 죽었다 살아나지 않는다(관리 노드가 순차 전이)
  - **재개방 조건**: R0~R2 실차에서 Nav2 노드 crash-restart 가 **1회라도** 관측되면 재개방
- E2E cleanup 순서 불변조건(부모 `ros2 launch` 먼저 kill → `pkill -9 -f "lib/nav2[_]"`, 브래킷 트릭 —
  `AGENTS.md §4`)은 회귀 실행 시 그대로 지킨다.
