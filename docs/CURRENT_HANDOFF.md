**코드 설명 깊이(4장)** — §96 에서 사용자가 이해한 방식 그대로:
모든 줄에 "무엇을 · 왜" → **C++ 문법은 처음 나올 때마다 풀이**(`explicit`·`const` 함수·초기화 목록·
`protected`·`template`·참조 `&`·`static_assert`·`enum` 등) → 실제 로봇 값으로 **숫자 따라가기** →
**강의 몇 장의 무엇**인지. 문법부터 쏟지 않고 "역할 → 선언부 → 함수 하나씩" 순서로 연다.

**세션 계획** — 한 세션에 한두 장, 약 5~6세션. 기본 순서 = 4 → 5 → 3 → 2 → 1 → 6·공통·7-3.

### §96 에서 확인·정정한 사실 — 재료로 바로 쓴다

- **IMU 방향**: 펌웨어가 `orientation_covariance[0] = -1`(방향 없음)로 보낸다 → EKF 는 IMU **회전 속도만** 쓴다
  (`ekf_real.yaml:122` 의 yaw=true 는 무시됨, `REAL_ROBOT_VALUES §1-k-7`). 본문 2-5 고침.
- **회전 속도 신뢰도**: 바퀴 vyaw 공분산 0.10 vs IMU 0.0025 (`.ino:1916`, `:1925`).
- **바퀴 간격 3개**: 물리 0.49 · 명령 0.62 · odom 0.859 m (`.ino:151~214`). 곡선에서 odom 회전 약 16% 과소.
- **SEARCH_BACK**: 커밋된 코드 = 0.03 m(`r10`). 본편 `realtake6` 1.10 m = 젯슨 시험 패치(`TERM_PROJECT §7`).
- **본편 `realtake6` 의 숨기지 않을 조건**(`0823_현황.md §13-12`): xy 전환 사람 손 · 실패판 > 성공판 ·
  SEARCH_BACK 시험 패치 · Nav2 yaw 0.10 미검토. 본문 6-2 에 조건 문장 넣음.
- **D항**: 끈 이유는 코드에 없다(`.ino:301` "recommended initial mode" 뿐). "잡음 때문으로 보인다" 까지만.
- **FF 기울기 335**: 모델 역함수(271)가 아니라 (0.02 m/s, 30 PWM) 고정점에서 **0.12 m/s 한 점**에 맞춘 값
