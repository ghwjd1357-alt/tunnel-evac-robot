## 4. B1 — 1.6.3 사건 계측 구현 (09:30~11:30) · 예약 41-g

계약 정본 = `MASTER_PLAN §7` 예약 41-g **"08-18 확정 계측 계약"**. 요약만 다시 적으면:

1. **사건 ring** — 판 간격 > `LOOP_GAP_EVENT_US`(초안 100ms) 또는 publish 실패 시 한 칸.
   칸 = `{epoch_ms, gap_us, phase, publish_slot, code}` · 깊이 16 · 넘침 수를 따로 센다.
2. **`epoch_ms` 는 30초 `TIME_SYNC` 동기 시각** — MCU 상대시각만 남기면 bag 수신 공백과
   대응이 안 되어 계약 미달이다.
3. 🔴 **`evt_seq`(단조 증가) + 부팅 직후 주입 사건 1건** — 이게 없으면 *"사건 0건"* 이
   *"ring 이 죽었다"* 와 구별되지 않는다. **§77.2 와 같은 자리다 — 부재는 관측이 아니다.**

**작업 순서 (하나씩 검증한다)**

```bash
# 노트북에서 — 보드 없이 되는 것부터 끝낸다
bash tools/rearm_gate_host_test.sh          # 기존 989 + 구조 11 이 그대로인지 먼저
python3 -m pytest tools/ -q                 # 기준선 확인 (착수 전)
# … 헤더 구현 후 …
bash tools/rearm_gate_host_test.sh          # 역회귀 — 숫자가 줄면 되돌린다
arduino-cli compile -b teensy:avr:teensy41 firmware/teensy_integrated_base_v1_4
```

**금지** — 누적 `loop_gap_max_us` 를 **지우지 않는다**(역회귀용). `phase_max_us` 7개·
`publish_max_us` 8개 배열의 개수·순서를 바꾸지 않는다. 안전 관련(`rearm_gate.h`
전이·`drive_wiring.h` 정지)은 **건드리지 않는다** — 오늘 것은 계측 추가뿐이다.

**FLASH/RAM** — `FIRMWARE_REBUILD §4` 기준점 대비 증가분을 적는다. 1.6.2 는
1407/1535(여유 128)였다. 🔴 **여유가 줄면 ring 깊이 16 을 8 로 낮춘다** — 계측을 넣겠다고
안전 여유를 먹지 않는다.
