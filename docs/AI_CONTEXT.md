# AI_CONTEXT.md — AI 입력 최적화 계약

> 목적은 **검토량을 줄이는 것**이 아니라 같은 원문·diff·게이트를 한 번에 전달해 모델 왕복과
> 중복 입력을 줄이는 것이다. 원문 정본 우선순위는 `AGENTS.md §2` 그대로다.

## 1. 사용법

구현자는 의도한 파일을, 검토자는 대상 커밋의 부모를 넣는다.

```bash
python3 tools/ai_context.py implement tools/ai_context.py docs/AI_CONTEXT.md
python3 tools/ai_context.py review --base <대상커밋^> --target <대상커밋>
```

출력은 현재 핸드오프, 역할별 테스트 절, 변경 표면별 필요한 정본 절을 한 패킷에 담는다.
검토 패킷은 `git diff --find-renames --find-copies` **전문을 자르지 않고** 마지막에 붙인다.
AI는 패킷의 `SOURCE` 머리말(경로·줄·sha256)로 원문 위치를 확인할 수 있다.

## 2. 품질 불변조건

1. `AGENTS.md`와 `CLAUDE.md`의 자동 진입 규칙은 패킷으로 대체하지 않는다.
2. `CURRENT_HANDOFF`와 역할별 게이트는 항상 들어간다. 구현 = `TEST_GATES §1`, 검토 = `§7`.
3. 여러 변경 표면은 합집합으로 라우팅한다. 한 표면의 문맥이 다른 표면 때문에 사라지지 않는다.
   한 파일이 여러 프로필에 동시에 맞아도 첫 일치에서 멈추지 않고 그 프로필들을 모두 합친다.
4. 등록되지 않은 경로가 하나라도 있으면 최적화를 포기하고 안전 정본 6개 전문을 넣는다.
5. platform-core·실차·Nav2·지도 표면은 `FREEZE_MANIFEST`와 해당 실차 정본을 생략하지 않는다.
6. 패킷은 읽기 편의용 파생물이다. 내용 충돌 시 source 원문과 `AGENTS.md §2` 우선순위를 따른다.
7. 토큰 목표를 맞추려고 diff, 부정 회귀, 역회귀, 독립 검토 또는 테스트를 줄이지 않는다.
8. Markdown 절 추출에서 **fenced code 내부의 `#`는 절 경계로 취급하지 않는다**. 닫히지 않은
   fence는 과잉 포함 방향으로 fail-closed 처리하고, 실제 fence 밖 동급 제목만 절을 끝낸다.

## 3. 측정·재검출 계약

- 🔴 **08-07 개정 (사용자 결정) — cold-start 판정이 비율에서 절대 상한으로 바뀌었다.**
  구판은 `ef25ad3` 대비 **30% 감소**를 요구했다. 기준점이 고정이라 사실이 쌓일수록 **구조적으로
  반드시 실패**하고, 그 압력이 같은 저장소의 반대 방향 게이트(`doc_check` 의 개수 주장 유지 ·
  `test_13` 의 예약 23 바이트 동일)와 정면 충돌했다 — 08-07 에 여유가 **41 바이트**까지 몰려
  규칙 한 줄을 못 쓰는 상태가 됐고, 08-06~07 에만 이 계약이 **다섯 번** 깨졌다.
  → 재는 대상을 바꾼다: **`AGENTS.md`+`CLAUDE.md`+`CURRENT_HANDOFF.md` ≤ 42,000 bytes 이고
  ≤ 13,500 o200k 토큰**(`test_14`·`test_15`, 상수 = `COLD_START_*`).
  ⚠ **이는 `ef25ad3` 대비 30% → 약 25% 로 완화다. 숨기지 않는다.** 상한을 지탱하는 규약은
  `AGENTS.md §5` 의 "핸드오프는 현재 묶음 + 미해결 보류만 유지"다.
- 바이트와 토큰을 **둘 다** 재는 이유: 한글은 바이트/토큰 비가 영문과 달라 한쪽만 재면 다른 쪽이
  조용히 넘친다. 토큰이 실제 문맥 비용이고, 바이트는 토크나이저가 없어도 도는 fail-closed 값이다.
  로컬 판정은 `tools/local_token_count.js` + VS Code 동봉 o200k vocabulary 로 한다(원문 외부
  전송 없음). Claude 자체 JSON usage 비교는 사용자가 별도 승인한 경우에만 보조 측정한다.
- `tools/ai_known_p0_p1.json`은 0719~0819 독립 검토 §80까지 나온 P0/P1 의무 **160개**를 각각 한 행으로
  고정한다. `tools/test_ai_context.py`는 Desktop에서 **`*검토현황.md` 접미사 규약**을
  지킨 파일을 그 앞의 이름·날짜에 관계없이 자동 발견해 제목/표 규칙 + 역사 특수형 3개로 끝까지
  훑고 **독립적으로 160개인지** 센 뒤, 각 행을
  독립 패킷으로 만들어 필요한 안전 앵커가
  있는지 전수 대조한다. 하나라도 빠지면 재검출률은 100%가 아니므로 실패한다.
- 🔴 **공개된 계수 상한 — 제목 깊이는 `###` 정확히 세 개다** (08-04 검토 §40.4). 같은 P1을
  `#### 39.6.1 P1 —`로 쓰면 스캐너가 **못 본다**. 즉 위의 "새 제목이 추가되면 즉시 테스트가
  실패한다"는 보장은 **`###` 깊이에서만** 참이다. 검토문을 쓸 때 P0/P1 제목은 반드시 `###`로
  적는다. 이 상한 자체가 계약이므로 `test_02c`가 `####` 합성 제목이 계수되지 않음을 회귀로
  고정한다 — 깊이를 넓히려면 그 회귀를 먼저 바꾼다.
- 🔴 **세 파일을 늘리기 전에 먼저 잰다.** ⚠ **토큰이 먼저 걸릴 수 있다 — bytes 여유만 보고
  늘리면 실패한다.** 늘려야 하면 **같은 묶음에서 어딘가를 줄이거나**, 상세를 이 세 파일이
  아니라 **링크로 연결된 문서**에 둔다(예산 밖이다). 08-06~07 에 구판 비율 계약이 다섯 번
  깨진 이력이 그 습관을 요구한다. 측정:

```bash
python3 -m unittest tools.test_ai_context.ContextRouterTest.test_14_cold_start_repository_input_is_at_least_30_percent_smaller
```
- 각 행의 앵커는 그 행의 경로가 선택한 **프로필 정본에서만** 충족돼야 한다. 항상 포함되는
  `CURRENT_HANDOFF`나 역할별 공통 게이트에 같은 말이 있다는 이유로 통과시키지 않는다. 프로필
  라우팅을 비운 부정 회귀에서는 160개가 전부 실패해야 한다.
- 앵커 대조는 모델 검토를 대체하지 않는다. 기존 pytest·colcon·공격 harness와 반대 AI의 독립
  검토를 그대로 수행한다. 알려진 결함 코퍼스 160/160는 **라우팅 회수율**, 실제 모델 재검출은
  별도 cold-start replay 결과로 함께 기록해 둘을 섞어 말하지 않는다.
- Desktop 검토문에 새 P0/P1 제목이 추가되면 역사 전수 수와 inventory 날짜별 수가 즉시 달라져
  테스트가 실패한다. 새 발견을 조용히 기존 상한 밖으로 자르지 않고, 같은 AI 최적화 묶음에서
  profile-only 앵커를 정한 뒤 inventory와 이 수치를 함께 올린다.
- 이 역사 재계수는 Desktop 검토 archive가 마운트된 **정본 개발 PC에서만** 강제된다. archive가
  없는 이식 환경에서는 해당 테스트를 skip하고 inventory 라우팅 회귀만 수행한다. 따라서 새
  발견 편입 게이트의 권위는 이 개발 PC의 `doc_check --strict`이며, portable CI가 대신 증명한다고
  주장하지 않는다.
- 검토 §38의 새 P1 두 건은 해결된 항목이 아니라 `MASTER_PLAN §7` **예약 24**의 미해결 의무다.
  profile-only 재검출 앵커는 **라이다 실측 소유 시점 D+0/D+1 정합**과
  **readiness flake 활성 정본 소유권 정합**이며, D+0 실행과 예약 21 구현에 섞지 않는다.
- 검토 §40의 새 P1 한 건도 해결 항목이 아니라 `MASTER_PLAN §7` **예약 26**의 미해결 의무다.
  profile-only 재검출 앵커는 **방법 B 계약 표면 재설계 결정의 소재**다. 2026-08-03 사용자
  결정은 §37.3 금지어 스윕을 위치 예외·표 셀 분해(방법 A)로 덧대는 것이 아니라 **계약 표면
  자체를 다시 설계해(방법 B) 스윕을 함께 제거**하는 것이었는데, `c7815f0`은 방법 A를 구현했고
  결정문은 저장소 어디에도 남지 않았다. 결정은 `MASTER_PLAN §8`에 복원했고 미구현 잔여는
  예약 26이 소유한다. **§37.3을 닫힌 것으로 인용하지 않는다.**
- **watchdog 정상 실측 기록 슬롯의 위치 계약**은 활성 문서 안의
  `watchdog-evidence-slot` 표식 두 쌍이 소유한다. 그 안에서 PASS/FAIL과 시간·프레임 실측값을
  회신과 대조한 문장만 허용하며, 실측 생략·회신 단독 승격은 같은 슬롯 안에서도 실패한다.

## 4. 공개된 상한과 fail-closed 복귀

파일명만으로 작업 의미를 완전히 증명할 수는 없다. 동적 생성 파일, 새 패키지, 새 확장자처럼
라우터가 모르는 경로는 `unknown=`에 표시되고 안전 정본 전문으로 복귀한다. 거짓 양성은 토큰을
더 쓰게 할 뿐 품질을 낮추지 않는다. 거짓 음성을 막기 위해 새 경로를 조용히 `docs`로 간주하지
않으며, 라우팅 규칙을 넓힐 때는 정상·미지·혼합·고위험 픽스처를 같이 추가한다.

watchdog 권위 검사는 Markdown 표를 셀 단위로 보고, 주어와 판정을 이웃한 두 문장으로 나눈
§37 재현형까지 결합해 검사한다. 그래도 자연어 전체의 동의어·세 문장 이상 분리·멀리 떨어진
상호참조를 정규식으로 전수할 수는 없다. 현재 의미 집합은 `tools/test_ai_context.py`의
`WATCHDOG_*` 상수와 저장 회귀가 상한이며, 이 밖의 표현을 “전부 검출”했다고 주장하지 않는다.
